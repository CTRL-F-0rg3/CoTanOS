CoTanOS — Booting Process & Architecture Specification

Technical documentation covering the low-level hardware initialization layer (ini/) and the 256xtr microkernel for the RISC-V architecture.

1. Project Design Goals

CoTanOS abandons legacy x86 standards and external firmware dependencies (such as traditional OpenSBI) to maintain complete control over the bare metal. The system is designed for native RISC-V 64-bit (rv64gc) architecture and custom target hardware.

  • Kernel Architecture: The 256xtr microkernel featuring an embedded network driver (krn/net) within kernel space for maximum performance.
  • Independence: A custom bootloader layer located in the ini/ directory, initializing the processor from the very first clock cycle.
  • Toolchain Environment: An isolated containerized build environment based on Arch Linux and RISC-V GCC.

2. Boot Sequence (`ini/` Bootloader)

The system startup consists of two critical low-level phases before transferring execution control to the 256xtr microkernel:

  1. Assembly Initialization (ini/boot.s): Takes control at address 0x80000000, sets up the processor stack, zeroes out the BSS section, and prepares the environment for C code execution.
  2. Hardware Initialization (ini/main.c): Configures basic I/O mechanisms (UART), sets up memory mapping foundations, and prepares for the core kernel handoff.
# Compilation and QEMU execution without external firmware wrappers
./run-compiler.sh riscv64-elf-gcc -march=rv64gc -mabi=lp64d -mcmodel=medany -nostdlib -ffreestanding -O2 -c ini/main.c -o ini/main.o
qemu-system-riscv64 -machine virt -cpu rv64 -smp 1 -m 128M -bios none -kernel ini/bootloader.elf
