1. Overview

The CoTanOS Storage Driver Suite provides a unified, bare-metal device driver stack for NVMe (1.4c and 2.0), AHCI/SATA (HDD, SSD), and AAC/AACRAID controllers running on RISC-V RV32 or RV64. It is written in C11 with an optional C++17 wrapper and has no dependency on libc, exceptions, or runtime support.

What it does

  • PCIe enumeration (ECAM + legacy stub + custom vtable)
  • NVMe: full command set, admin + I/O queues, namespaces, SMART, firmware, ZNS, KV, Reservations, Directives, SR-IOV, multipath detection
  • AHCI: HBA/port lifecycle, ATA IDENTIFY, DMA and NCQ R/W, TRIM, SMART, secure erase, sanitize, hotplug, error recovery
  • AAC: mailbox init, FIB queue, LD I/O, PD SMART via SCSI ATA PASS-THROUGH
  • Unified async block API (submit / poll / completion callback)
  • Hardware-free selftest harness

What it does not do

  • No memory allocation: every buffer comes from stor_dma_alloc (kernel-supplied)
  • No interrupt handling: MSI-X / INTx wiring is caller's responsibility
  • No libc, no exceptions, no std::vector, no malloc
  • No NVMe-oF, no port multiplier, no ATAPI, no IOMMU management (delegated)
  • No filesystems, no partition tables, no caching layer

3.2 stor_mm.h / stor_mm.c

The kernel registers a stor_mm_ops_t vtable at boot. Every driver allocation and MMIO map goes through it. This is the only integration point required to make the driver work on a new platform.

typedef struct {
    int   (*alloc_dma)(size_t size, size_t align,
                       dma_addr_t *phys, void **virt);
    void (*free_dma)(dma_addr_t phys, void *virt, size_t size);
    int   (*map_mmio)(paddr_t phys, size_t size, vaddr_t *virt);
    void (*unmap_mmio)(vaddr_t virt, size_t size);
    void *(*phys_to_virt)(paddr_t phys);
    paddr_t (*virt_to_phys)(const void *virt);
    void *(*kmalloc_aligned)(size_t size, size_t align);
    void  (*kfree_aligned)(void *ptr, size_t size);
} stor_mm_ops_t;

Register with stor_mm_init(&ops). When the vtable is absent, all allocation calls return STOR_ERR_NOT_SUPPORTED; the driver core never assumes success.

DMA contract (kernel must honour):

  • alloc_dma returns physically contiguous, zeroed, DMA-coherent memory.
  • *phys is the address visible to the device. If an IOMMU is present, this is the IOVA; the driver does not translate further.
  • *virt is a kernel VA in the direct map, suitable for stor_mem_copy.
  • align is honoured exactly (power of two).

3.4 Unified block layer

Every device — NVMe namespace, SATA HDD/SSD, AAC logical volume — exposes the same async interface: stor_blk_dev_t.

struct stor_blk_dev {
    const char *name, *serial, *model, *fw_rev;
    u64         capacity_sectors, capacity_bytes;
    u32         sector_size, physical_block_size, queue_depth;
    u32         max_transfer_sectors, discard_granularity;
    bool        rotational, removable, write_cache;
    bool        trim_supported, secure_erase_supported, zoned;
    u64         zone_size_sectors, zone_count;
    stor_blk_type_t type;
    void       *priv;    // driver context (namespace/port/ld)
    int       (*submit)(stor_blk_dev_t *, stor_blk_req_t *);
    int       (*poll)(stor_blk_dev_t *, u32 budget);
    int       (*flush_queue)(stor_blk_dev_t *);
    int       (*quiesce)(stor_blk_dev_t *);
    int       (*resume)(stor_blk_dev_t *);
    int       (*get_health)(stor_blk_dev_t *, stor_blk_health_t *);
    int       (*get_geometry)(stor_blk_dev_t *, stor_blk_geometry_t *);
};

Async submit / completion model

stor_blk_req_t req = {0};
req.op       = STOR_BLK_READ;
req.lba      = 0x10000;
req.nsect    = 8;
req.buf      = my_buffer;
req.cookie   = &my_context;
req.complete = my_callback;

int rc = stor_blk_submit(dev, &req);
// If rc != STOR_OK, callback already fired with the error.
// Otherwise, callback will fire later from stor_blk_poll(dev, budget)
// or from the controller's IRQ handler.
Callback rules Completion callbacks run in the caller's context — either from stor_blk_poll or from the IRQ top-half if the controller was wired to MSI-X. They must not block and must not submit new requests from within the callback.

Sync wrappers

For boot code, selftests, or diagnostics:

int stor_blk_read_sync(dev, lba, nsect, buf);       // 30 s timeout
int stor_blk_write_sync(dev, lba, nsect, buf);
int stor_blk_flush_sync(dev);
int stor_blk_discard_sync(dev, lba, nsect);

These spin on stor_blk_poll internally and return the final status. They are not intended for hot I/O.

4. NVMe (1.4c + 2.0)

4.1 Controller bring-up

stor_nvme_ctrl_t ctrl;
stor_pci_device_t pci = {...};

// 1. Map BAR0, enable memory + bus master.
stor_nvme_probe(&pci, &ctrl);

// 2. Reset, program admin queue, enable, Identify Controller.
stor_nvme_init(&ctrl);

// 3. Create I/O queues (CQ + SQ per qid, qid 1..n).
stor_nvme_create_io_queues(&ctrl, 4, 128);

// 4. Enumerate namespaces, build stor_blk_dev_t per NS.
stor_nvme_scan_namespaces(&ctrl);

Behind the scenes:

  • Reset: CC.EN=0, poll CSTS.RDY==0, timeout from CAP.TO (default 5 s).
  • Admin queue: 64 entries, page-aligned SQ + CQ. AQA programmed as (depth-1) | ((depth-1)<<16). ASQ/ACQ written as two 32-bit MMIO accesses.
  • Enable: CC.EN=1, IOSQES=6, IOCQES=4, MPS=0 (4 KiB pages). Poll CSTS.RDY==1.
  • Identify Controller: CNS=0x01, 4096-byte DMA buffer, parsed into ctrl->id_ctrl.

Admin command submission

int stor_nvme_admin_cmd(stor_nvme_ctrl_t *ctrl,
                        const stor_nvme_sqe_t *sqe,
                        stor_nvme_cqe_t *cqe_out,
                        u32 timeout_ms);

Synchronous by design — admin commands are rare and small. Sequence:

  1. Copy SQE into the tail slot of the admin SQ, stamp CID = next_cid++.
  2. Advance tail, write SQ doorbell.
  3. Poll CQ for a CQE with phase == ctrl->phase.
  4. Advance CQ head, ring CQ doorbell. If head wrapped to 0, flip phase.
  5. Decode SC/SCT into STOR_ERR_*, return.

4.4 Zoned Namespace (ZNS)

CSI = 0x02. ZNS-capable namespaces are detected during stor_nvme_scan_namespaces and probed with stor_nvme_zns_probe_ns:

for (u32 i = 0; i < ctrl.namespace_count; i++) {
    stor_nvme_ns_t *ns = ctrl.ns[i];
    stor_nvme_zns_probe_ns(ns);   // sets ns->zoned, zone_size, zone_count
}

CSI position fix NVMe spec places CSI at CDW11[31:24] (byte 47) for Identify commands with CNS ≥ 0x05. The header's stor_nvme_identify_params_t struct is a doc-only convenience; the driver bypasses it and builds CDWs directly to avoid miscompilation of the layout.

Multipath

Baseline: detect CAP.CRMS (multi-controller capable). If set, log a warning and return STOR_ERR_NOT_SUPPORTED; full routing requires NVMe-oF fabric registration, which is out of scope. Callers should address each controller independently.

5. AHCI / SATA

5.1 HBA bring-up

stor_ahci_hba_t hba;
stor_ahci_probe(&pci, &hba);      // BAR5 map, enable mem + busmaster
stor_ahci_init(&hba);              // HBA reset, port scan, per-port init

for (u32 p = 0; p < 32; p++) {
    if (hba.ports[p].ready)
        stor_ahci_attach_blk(&hba, p);   // IDENTIFY -> stor_blk_dev_t
}

Sequence:

  1. HBA reset: GHC.AE=1 → GHC.HR=1 → poll HR=0 → re-assert AE=1.
  2. Capability read: CAP, CAP2, PI. NCS = min(CAP.NCS+1, 32), NP = CAP.NP+1.
  3. Port scan: for each bit set in PI, run per-port init.
  4. Per-port init: stop engine, check PxSSTS.DET, allocate Cmd List (1 KiB) + FIS (256 B) + 32 Cmd Tables (256 B each), program PxCLB/PxFB, enable interrupts, start engine.

5.2 Transport layer

FIS construction

Register Host-to-Device FIS (20 bytes) is built by ahci_fis_h2d_build:

void ahci_fis_h2d_build(stor_fis_reg_h2d_t *fis,
                        u8 cmd, u8 device,
                        u64 lba, u16 count,
                        u8 features_lo, u8 features_hi, u8 control);

LBA48 is split across lba0..lba5. device is 0x40 (LBA mode + obsolete LBA bit). icc = 0x80 (command flag).

PRDT builder

Each PRDT entry describes up to 4 MiB (22-bit DBC). The driver splits a physically contiguous buffer into up to 8 entries (32 MiB per command). Larger transfers return STOR_ERR_RANGE; caller must split at a higher layer.

Command submission

All non-NCQ commands use tag 0 (the classic path). NCQ commands allocate the lowest free tag from the 32-bit slot_in_use bitmap. The tag is encoded in FIS.features_lo[7:3] (FPDMA QUEUED requirement).

// NCQ read example
u32 tag = stor_ctz32(~slot_in_use);   // lowest free tag
u8  features = (u8)((tag & 0x1F) << 3);
ahci_issue_cmd(hba, p, tag, prdtl, write=false);
// Sets PxSACT bit (NCQ), then PxCI bit

Completion

Poll on PxCI. When the tag's bit clears:

  • PxTFD.STS.ERR set → STOR_ERR_IO
  • PxIS.TFES set → STOR_ERR_IO
  • Otherwise → STOR_OK

On error, the driver clears PxIS and PxSERR, and the caller may invoke ahci_error_recovery (stop → COMRESET → restart).

5.3 TRIM, SMART, secure erase, recovery

TRIM (DATA SET MANAGEMENT)

ATA command 0x06, FEATURES = 0x01. Payload is a list of 8-byte LBA ranges: { u16 nlb; u16 rsvd; u64 slba; }. Up to 64 ranges per command (512 B payload, 1 PRDT entry).

int stor_ahci_port_trim(hba, port, ranges, range_bytes, ranges_phys);

SMART

ATA command 0xB0 with FEATURES = 0xD0. The ATA signature C2 4F C2 is encoded as LBA = 0x4F00C2. Returns 512 bytes of SMART/health data.

Secure erase

Two-step protocol:

  1. SECURITY ERASE PREPARE (0xF3) — no data.
  2. SECURITY ERASE UNIT (0xF4) — 512-byte payload, first 32 bytes = password. features_lo = 0x02 selects enhanced (crypto) erase.

Timeout: 5 minutes (typical full-disk erase).

Sanitize

ATA command 0xB4. Feature codes: 0x00 block erase, 0x04 sanitize (crypto erase on SED). Timeout: 5 minutes.

Error recovery

On any I/O error or timeout, the driver executes:

port_stop -> clear PxSERR + PxIS -> COMRESET -> port_start

Caller's request fails with STOR_ERR_IO; retry policy is caller's responsibility.

6. AAC / AACRAID

Adaptec / PMC RAID controllers. Match: PCI class 0x01, subclass 0x04 (RAID).

Mailbox interface

MMIO registers at BAR0:

OffsetNameWidth
0x00MAILBOX_CMDu32 (write command opcode)
0x04MAILBOX_STATUSu32 (BUSY / OK / ERROR)
0x20MAILBOX_DATA8 × u32 (32 B arguments)

Mailbox submission: load 8 argument bytes → set BUSY → write command → poll BUSY clear → check ERROR → read result.

Init sequence

  1. Reset: mailbox 0x0E (RESET_ADAPTER).
  2. Get info: mailbox 0x0A (GET_CTLR_INFO). Real firmware returns a FIB with adapter details; baseline stubs the response with fixed values.
  3. FIB queue: allocate 64 × 512 B DMA block. Each FIB is one outstanding request.

FIB structure

FIB (Fibre Information Block) — 512 bytes total, packed:

typedef struct __packed {
    u32 cmd;        // AAC_CMD_xxx
    u32 flags;      // bit 0 async, bits 1-2 data direction
    u32 size;       // data payload size in bytes
    u32 sgl_number; // SGL entry count
    u32 lba;        // starting LBA
    u32 handle;     // LD or PD handle
    u32 count;      // sector count
    u32 rsvd[8];
} stor_aac_fib_header_t;   // 64 bytes

typedef struct __packed {
    u64 sgl_addr;
    u32 sgl_length;
    u32 sgl_flags;
} stor_aac_sgl_t;          // 16 bytes each

LD I/O

READ_64 (0x04) / WRITE_64 (0x05) via FIB, 512-byte sectors, 64-bit LBA. Single SGL entry per command. Submission is synchronous (mailbox 0x11 returns OK = accepted).

PD SMART passthrough

SCSI ATA PASS-THROUGH (16) CDB 0x85 via FIB:

[0]0x85ATA PASS-THROUGH (16)

Integration steps

  1. Implement stor_mm_ops_t in the kernel: alloc_dma, free_dma, map_mmio, unmap_mmio, phys_to_virt, virt_to_phys, kmalloc_aligned, kfree_aligned.
  2. Call stor_mm_init(&ops) early in boot.
  3. Call stor_pci_init_ecam(phys, size, 0, 255) with the platform's ECAM base. Or stor_pci_init_custom if using a non-standard bridge.
  4. Call stor_log_fn = your_log_function so driver output reaches the kernel log.
  5. Call stor_selftest_run_all() (with stor_selftest_set_hw_context(&ctx) if hardware is present) to validate the setup.
  6. Instantiate controllers: either manually (stor_nvme_probe + stor_nvme_init etc.) or via stor::cpp::StorageManager::bring_up().

MSI-X / IRQ wiring (out of scope of this driver)

The driver is polling-only in this baseline. To enable interrupts:

  1. Add MSI-X capability walk to stor_pci.c.
  2. Program MSI-X table entries to point at your platform's interrupt controller.
  3. Install an IRQ handler that calls stor_nvme_poll_completions(ctrl, qid, budget) (NVMe) or stor_blk_poll(dev, budget) (unified layer).
  4. For AHCI: the driver already programs PxIE; add stor_ahci_poll_port(hba, port) in the IRQ top-half.
