1. Overview

DP/HDMI Core Driver is a complete bare-metal driver supporting both DisplayPort 1.4a and HDMI 2.0, written in C11 (core) and C++17 (convenience layer), targeted at the CoTanOS operating system on RISC-V (RV32/RV64).

The driver implements the full DisplayPort protocol stack — from low-level MMIO access, through the AUX channel, link training, EDID/CEA-861 parsing, audio/video stream handling, HDCP (versions 1.x and 2.2), Multi-Stream Transport (MST), Display Stream Compression (DSC), Panel Self Refresh (PSR) and Advanced Link Power Management (ALPM), all the way up to a regression-test harness.

Design philosophy: The C core (blocks 1–8) does all the heavy lifting and assumes no operating system or libc. The C++ layer (dp_controller.hpp) is purely a convenience wrapper — it provides RAII, strong types, callbacks, and orchestration. It does not duplicate DP logic.

1.1. Key Features

  • Zero runtime dependencies — no malloc, no threads, no libc (only <stdint.h>, <stdbool.h>, <stddef.h>).
  • Bare-metal MMIO — custom readl/writel with RISC-V fence barriers.
  • Asynchronous HDCP state machine — non-blocking, driven from timer/HPD.
  • Software cryptography — SHA-1, SHA-256, HMAC-SHA256, AES-128 (ECB/CBC), 2048-bit bignum (Montgomery CIOS).
  • Full DPCD — every DP 1.4a register including MST, DSC, HDCP, PSR, ALPM.
  • VIC table — full CEA-861 table with 45 entries (SD/HD/1080p/720p/UHD/4K DCI).
  • Regression tests — 21 tests, covering SW-only (SHA/AES/bignum/DSC PPS) and HW (link training).

4.3. MMIO Intrinsics

static inline void __raw_writeb(u8 val, volatile void __iomem *addr)
{
    __asm__ __volatile__ ("sb %0, 0(%1)" : : "r" (val), "r" (addr) : "memory");
}
/* writew (sh), writel (sw), writeq (sd), readb (lb), readw (lh), readl (lw), readq (ld) */

Synchronized variants: readb/w/l/q(), writeb/w/l/q() — with __io_*() barriers. Relaxed variants: _relaxed — no barriers. Aliases: ioread*/iowrite*.

4.4. AUX Transactions

The AUX channel carries a 20-bit address, max 16 B payload, with native commands (0x08/0x09) and I2C commands (0x00–0x05). The dispatcher dp_aux_transaction() handles:

StatusDispatcher Action
DP_AUX_TRANSACTION_COMPLETEReturns DP_OK
DP_AUX_TRANSACTION_DEFERREDExponential backoff 100 µs → 8 ms, retry up to 7×
DP_AUX_TRANSACTION_NACKShort retry 100 µs, retry up to 7×
DP_AUX_TRANSACTION_TIMEOUTShort retry 100 µs, retry up to 7×
DP_AUX_TRANSACTION_FAILEDImmediate failure (HW error)

4.4.1. DPCD Wrappers

int dp_aux_read_dpcd (dp_controller_t *c, u32 addr, u8 *buf, u32 len);
int dp_aux_write_dpcd(dp_controller_t *c, u32 addr, const u8 *buf, u32 len);

Split long transfers into 16 B chunks (read reply) / 16 B (write payload).

4.4.2. I2C-over-AUX

int dp_aux_i2c_read (dp_controller_t *c, u8 i2c_addr, u32 offset, u8 *buf, u32 len);
int dp_aux_i2c_write(dp_controller_t *c, u8 i2c_addr, u32 offset, const u8 *buf, u32 len);
  • 1-byte offset for ≤0xFF (typical EDID), 2-byte (high-first) for larger
  • MOT (Middle-of-Transaction) set in the offset write, then in every non-final chunk
  • 7-bit slave addresses: 0x50 = EDID, 0x3A = HDCP

4.5. Spinlocks, Mutexes, Semaphores

Built on amoadd.w.aqrl / lr.w.aqrl / sc.w.aqrl:

  • dp_spinlock_t — test-and-set with cpu_pause() in the loop
  • dp_mutex_t — binary semaphore with a counter
  • dp_semaphore_t — counter + waiters

5. Block 2 — Link Training

The standard DP link training procedure: Clock Recovery (CR, TP1) → Channel Equalization (EQ, TP2 or TP3).

5.1. CR Sequence

  1. Read DP_MAX_LINK_RATE and DP_MAX_LANE_COUNT from the sink DPCD
  2. Write DP_LINK_BW_SET and DP_LANE_COUNT_SET (plus Enhanced Frame if supported)
  3. Write DP_TRAINING_PATTERN_SET = 0x01 (TP1)
  4. Write VS/PE for each lane (start: VS=0, PE=0)
  5. Loop (max 10 iterations):
    • Read DP_LANE0_1_STATUS + DP_LANE2_3_STATUS
    • Check CR_DONE for all active lanes
    • Read DP_ADJUST_REQUEST (lane01 + lane23)
    • Apply new VS/PE (clamped to rate-dependent max PE)

5.2. EQ Sequence

Same as CR, but TP2 (RBR/HBR/HBR2) or TP3 (HBR3), max 10 iterations, checking EQ_DONE + SYMBOL_LOCKED plus INTERLANE_ALIGN_DONE.

5.3. Rate-dependent PE limits

RateMax VSMax PE
RBR (1.62 Gbps)30
HBR (2.70 Gbps)31
HBR2 (5.40 Gbps)33
HBR3 (8.10 Gbps)33

6. Block 3 — EDID / CEA-861 / HDMI DDC

EDID read and parse (base block 128 B + extensions), CEA-861, HDMI VSDB, ELD.

6.1. EDID Read

Over DP: dp_edid_read() reads the base block 128 B via I2C-over-AUX at address 0x50. Then (if ext_block_count > 0) it reads blocks 1–2 looking for CEA-861 (tag 0x02).

Over HDMI: hdmi_edid_read() uses DDC (3-register CTL/ADDR/DATA model), max 8 blocks = 1024 B.

6.2. Base Block Parsing

dp_edid_parse() returns an array of edid_timing_t composed of:

  • Established timings — 11 entries from a table (640×480@60 → 1280×1024@75)
  • Standard timings — 8 entries (aspect ratio + refresh → hactive/vactive)
  • Detailed timing descriptors (DTD) — 4 entries with full pixel clock and blanking

6.3. CEA-861 Parser

cea861_parse_data_blocks() iterates over all Data Blocks:

TagTypeWhat is parsed
0x01AudioShort Audio Descriptors (SAD)
0x02VideoVIC (CEA-861 Video Identification Codes)
0x03VendorHDMI VSDB (OUI, physical address, deep color, max TMDS, HDMI VIC)
0x04SpeakerSpeaker allocation

6.4. ELD (EDID Like Data)

dp_edid_fill_eld_cea() produces a HDA-compatible ELD structure used by audio to build PCM constraints. The ELD contains:

  • EDID version + baseline length
  • Speaker allocation (3 B)
  • SAD array (15 × 3 B)
  • HDMI VSDB (presence, length, flags, CEC address)

7.3. Stream Management

Two API variants:

  • Single-mode: dp_stream_set_timing() + dp_stream_enable() + dp_stream_disable()
  • Multi-mode (MST): dp_stream_set_timing_ex() + dp_stream_enable_ex() + dp_stream_disable_ex()

The _ex variant operates on dp_driver_state_t and tracks vc_payload_id, required for MST.

7.4. MSA Register Building

dp_msa_compute() + dp_msa_write_hw() translate dp_timing_spec_t into:

  • MSA_MISC0 — color format, sync clock, frame start
  • MSA_MISC1 — BPC, dynamic range, YUV420 VBLANK
  • HORIZONTAL_TOTAL/START/ACTIVE/BLANKING
  • VERTICAL_TOTAL/START/ACTIVE/BLANKING
  • PIXEL_CLOCK_RATE (kHz)

For interlaced modes all vertical fields are divided by 2 (per-field registers).

7.5. MST (Multi-Stream Transport)

  • Wire format: [link_hi][link_lo][msg_type][data ≤48B] (max 51 B, fits in 64 B FIFO)

8. Block 5 — Audio (ALSA-like)

Audio layer modeled after ALSA, but without kernel dependencies. Contains:

  • dp_snd_card_t — card with PCM, controls, ELD, SAD
  • dp_pcm_substream_t — ring buffer, hw_ptr, appl_ptr, period callback
  • dp_pcm_hardware_t — constraints (format/rate/channels/period/buffer)
  • dp_pcm_hw_params_t — parameters like snd_pcm_hw_params
  • dp_snd_kcontrol_t — simple controls (volume, switch, IEC958)

8.1. Structures

8.2. ELD and Constraints

dp_eld_parse() parses the ELD from DPCD (version, baseline, SAD count, speaker allocation, SAD array). dp_pcm_build_constraints_from_eld() computes:

  • format_mask — S16/S24/S32 LE (based on max BPC in SAD)
  • rate_min/max — 32 000 – 192 000 Hz
  • channels_min/max — 2 up to max from SAD
  • period_bytes_min/max, periods_min/max, buffer_bytes_max

8.3. CEA Channel Allocation

Table of 22 entries mapping CEA CA index → speaker layout (FL/FR/FC/LFE/RL/RR/…). CA selection: dp_cea_select_ca(spk_mask, channels) prefers exact match, falls back to a CA with the same channel count, then to stereo.

8.4. Audio InfoFrame

dp_audio_build_infoframe() builds a DP Audio InfoFrame packet (0x84/0x1b/0x11<<2), with fields:

  • CC02_CT47 — channel count - 1 (bits 2:0), coding type (bits 6:4)
  • SS01_SF24 — sample size, sample frequency
  • CA — CEA channel allocation index

dp_audio_pack_sdp_infoframe() packs into SDP header + 2 × u32 payload.

8.5. HDMI Audio InfoFrame

hdmi_audio_infoframe_pack() builds the standard 12-byte packet with checksum and sends it through HDMI_REG_INFOFRAME_CTL/DATA registers.

9. Block 6 — HDCP 1.x / 2.2

Largest block (~3020 LOC). Contains the complete software cryptographic stack required by HDCP: SHA-1, SHA-256, HMAC-SHA256, AES-128 (ECB/CBC), 2048-bit bignum (Montgomery CIOS), RSA-2048 public op.

9.1. Crypto Primitives

SHA-256HDCP 2.2 — certificate hashing, KDF
HMAC-SHA256HDCP 2.2 — kd, k_priv, k_pub, H', L'
AES-128 ECBHDCP 2.2 — e_km, e_kh_km
AES-128 CBCHDCP 2.2 — edkey_ks
RSA-2048HDCP 2.2 — cert verify (DCP root), kPub_km
Montgomery CIOSRSA-2048 modexp

9.2. HDCP 1.x — Full Flow

  1. Read Bksv (5 B), validate (20 ones)
  2. SRM check (if loaded)
  3. Generate AKSV (20 ones), write An + AKSV + AINFO
  4. Compute Km = cipher(AKSV, An) — HW cipher
  5. Read An' (RX changed it), compute R0 = cipher(An', Km)
  6. Write R0, read Ri
  7. If repeater: read BStatus + KSV FIFO, compute V = SHA-1(KSV || Bksv || M0), compare with V'

10. Block 7 — DSC / PSR / ALPM

10.1. DSC (Display Stream Compression)

10.1.1. PPS Encode/Decode

Complete implementation of dp_dsc_pps_encode() (87 bytes + reserved zero to 128) and dp_dsc_pps_decode(). All VESA DSC 1.2a fields:

  • dsc_version_major/minor, bits_per_component, linebuf_depth, block_pred_enable
  • bits_per_pixel (fixed-point ×16), pic_width/height, slice_width/height, chunk_size
  • initial_xmit_delay, initial_dec_delay, initial_scale_value, scale_increment/decrement_interval
  • first_line_bpg_offset, nfl_bpg_offset, slice_bpg_offset, initial_offset, final_offset
  • flatness_min_qp, flatness_max_qp, rc_model_size, rc_edge_factor, rc_quant_incr_limit0/1
  • rc_tgt_offset_lo/hi, rc_buf_thresh[14], rc_range_params[15][2]

10.1.2. PPS Compute

dp_dsc_compute_pps() — automatic PPS calculation from timing (pic_width/height, bpp, bpc):

  • All VESA baseline fields (8bpc/8bpp)
  • Tables dsc_default_rc_buf_thresh[14] and dsc_default_rc_range_params[15][3]

10.1.3. Slice Calculation

dp_dsc_calc_slices() selects:

  • slices_per_line — smallest power-of-two divisor satisfying max_slice_width
  • slices_per_column — prefers full height, falls back to 2×
  • Total ≤32, per VESA DSC

10.2. PSR (Panel Self Refresh)

dp_psr_enable() reads DP_PSR_SUPPORT + DP_PSR_CAPS from DPCD, computes setup time (bit 3:1 → 330 µs…0 µs table), programs HW timers:

  • DP_REG_PSR_TIMER_IDLE (0x348) = setup + 20 ms
  • DP_REG_PSR_TIMER_WAKEUP (0x34C) = 2 ms
  • DP_REG_PSR_CTL (0x340) = EN | IRQ_EN | AUTO_EXIT

Polling: dp_psr_poll() returns 0=idle, 1=active, 2=exiting, -1=error. dp_psr_frame_committed() is called before a new frame and forces exit.

10.3. ALPM (Advanced Link Power Management)

Full implementation with AUX-less wakeup:

  • DPCD: ALPM_CAP (bit 7 at 0x00E), ALPM_CTRL (0x221), ALPM_STATUS (0x222)
  • HW: DP_REG_ALPM_CTL (0x360), STATUS (0x364), TIMER_IDLE/WAKEUP (0x368/0x36C), WAKEUP_CFG (0x374), IRQ_* (0x378/0x37C)
int dp_alpm_configure(dp_controller_t *c, u32 cfg);
/* cfg: bit0=enable, bit1=AUX-less, bit2=lock-error HPD,
 *      bits 8..15=idle timer (ms), bits 16..23=wake timer (ms) */

int dp_alpm_poll (dp_controller_t *c);
int dp_alpm_wake (dp_controller_t *c);

10.4. PM (Power Management) Driver

Stateful helper managing DSC/PSR/ALPM together:

int dp_pm_activity    (dp_controller_t *c);   // reset timer + wake
int dp_pm_idle_tick   (dp_controller_t *c);   // poll PSR+ALPM, deactivate on error

16.5. Porting to Another IP Core

  1. Change dp_hardware_registers_t in dp_core.h to match your IP
  2. Change #define DP_REG_* in dp_core.c to your IP's offsets
  3. Change hdmi_ddc_xfer() for your DDC model
  4. Change hdcp1_cipher_* if your HDCP 1.x cipher has different registers
  5. Change dp_dsc_hw_write_pps() if the PPS window size differs
  6. Run dp_selftest_run_all() — SW tests confirm port correctness

18. Known Limitations

The following are intentional simplifications — candidates for future expansion.
  • HDCP 1.x cipher — requires a hardware block; a SW implementation requires a DCP LLC license (not included)
  • DCP root key — embedded 2048-bit public key; for production load from firmware
  • MST PBN — approximation as pixel_clock × bpp; production requires per-slice slot negotiation
  • DSC on complex modes — PPS compute is 8bpc/8bpp baseline; for 10/12bpc, extend RC tables
  • EDID > 2 extensions — dp_edid_read reads blocks 1–2 only (bytes 128–383); higher require segment pointer (TODO in hdmi_ddc_xfer)
  • HDMI VIC parse — best-effort iteration over 0xEx bytes; not full CEA-861-G
  • VIC → timing — pclk/hblank/vblank for VIC in standard timings are approximated (full table only for VIC lookup)
  • RNG — placeholder (xorshift + time); use HW RNG in production
  • DMA ring — caller-provided pointer; no built-in DMA allocator
  • MST topology — HDCP 2.2 repeater requires integration with Block 4 MST (partially done)
